# Independent Review Agent — proposed, awaiting implementation approval

Goal: independently review the exact implementation artifact before any human deployment approval, automatically return actionable findings to the implementer, and stop after three review attempts per authorized implementation revision. Attempt one reviews the first candidate; at most two automatic correction rounds follow.

1. Reconcile the active worker release with canonical source read-only. Inventory relevant runtime differences and operator wrapper contracts; retain existing operational fixes. Do not copy production configuration.
2. Extend backend/core/agent_state.py and an ordered reversible migration after 0019 (recheck numbering) with review queue/running states and review phase. Persist review cycle, attempt ordinal, implementation revision/run, candidate digest, verdict, structured findings, reviewer thread/turn and validation evidence. Unique cycle/attempt identity and lease fencing make retries idempotent. Worker retries must not reset the three-attempt budget.
3. Add backend/core/codex_review.py with a fresh reviewer context independent of the implementer thread. Review a frozen candidate snapshot read-only, without database/signing/deployment credentials. Supply approved plan, diff (including untracked files), validation evidence and repository instructions. Treat source and tool output as untrusted input. Reviewer returns pass/changes_requested/blocked plus findings; malformed output, timeout or missing evidence fails closed. No automatic approval by model prose.
4. Wire backend/agent_worker.py, backend/core/agent_worker.py and backend/services/agent_worker_service.py: implementation completion queues independent review transactionally instead of exposing deployable review_ready. Findings queue a correction on the existing authorized implementation branch/thread. Each correction captures a new digest and queues the next review. Third failure enters blocked human attention; cancellation, lease loss, unavailable quota or executor failure cannot create duplicate runs or deployable states.
5. In backend/services/agent_service.py, backend/routers/agent.py and backend/models/agent_models.py, gate deployment approval on a passing independent review of the current revision AND exact candidate digest. Any edit invalidates the pass. Persist audit events for each handoff and verdict. Reviewer never creates deployment approval. Preserve existing QA-to-production and user approval boundaries.
6. Expose review progress, attempts and findings in the existing frontend card detail; no new deployment automation. Verify Android handling before enabling either repository scope; unsupported scopes must fail closed, not bypass review.
7. Tests: first-pass success; fail/fix/pass; third failure; invalid verdict; stale digest/revision; changed untracked file; duplicate completion; expired lease; crash/retry budget; cancellation; quota unavailable; forbidden deployment without matching review; explicit human approval still required. Use mocked SDK/DB tests and synthetic snapshot integration tests. Run focused suites followed by applicable backend checks; no live database or service tests.
8. Rollout only after separate deployment approval: reversible schema first, compatible readers/API, worker capability and sandbox probe, then review enablement. Recheck worker release provenance and in-flight cards. No grandfathered automatic pass. Rollback stops new review scheduling while preserving audit data; no rollback may silently restore unreviewed deployment.

Approval requested: implement and test this plan only in the isolated development worktree. Deployment, operational wrappers, service configuration and databases remain separately approved.
